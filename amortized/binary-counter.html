Binary Counter 二進位計數器

一個 k-bit 計數器，每次 INCREMENT 的成本是翻轉的位元數。最壞一次翻 k 個，所以 n 次是 \(O(nk)\)——一樣對但不緊。數一數每個位元各翻幾次，就得到 \(<2n\)。

設定

  • 計數器有 k 個位元，從右邊數起記為 \(b_0, b_1, \dots, b_{k-1}\)（\(b_0\) 是最低位）。一開始 count = 0，例如 k = 5 時是 0 0 0 0 0。
  • INCREMENT 把 count 加 1，成本 = 被翻轉的位元數：
之前之後成本說明
0 0 1 0 1（5）0 0 1 1 0（6）2\(b_0\): 1→0，\(b_1\): 0→1
1 1 1 1 1（MAX）0 0 0 0 0（0）k = 5全部是 1 時，INCREMENT 讓所有位元歸零（繞回）

規則：從 \(b_0\) 往上，把連續的 1 都翻成 0（進位），再把遇到的第一個 0 翻成 1。

粗略分析：\(O(nk)\)

  • 單次 INCREMENT 最壞？ \(O(k)\)：所有位元都是 1 時要翻 k 個。
  • n 次最壞總共？ \(O(nk)\)。正確，但不緊——大部分 INCREMENT 只翻一兩個位元。

逐步執行

黃色是這次翻轉的位元。注意下面那張「已翻次數」表：\(b_0\) 每次都翻，\(b_1\) 每 2 次翻一次，\(b_2\) 每 4 次……；右下圖的黑線（累計成本）永遠在綠色虛線 \(2n\) 之下，離橘色的粗略上界 \(nk\) 很遠。

關鍵觀察：每個位元多久翻一次

p.12\(b_i\) 每 \(2^i\) 次 INCREMENT 才翻一次。精確地說：第 x 次 INCREMENT 會翻 \(b_i\) ⇔ \(x\) 可以被 \(2^i\) 整除。

為什麼？第 x 次 INCREMENT 把 \(x-1\) 變成 \(x\)，翻掉的是 \(x-1\) 結尾那串連續的 1，再加上它上面的那個 0——也就是 \(b_0,\dots,b_t\)，其中 \(t\) = \(x\) 結尾 0 的個數。所以 \(b_i\) 被翻 ⇔ \(x\) 至少有 \(i\) 個結尾 0 ⇔ \(2^i \mid x\)。在 \(1..n\) 中這樣的 x 有 \(\lfloor n/2^i\rfloor\) 個。

Aggregate 分析：\(<2n\)

$$\text{總成本}=\sum_{i=0}^{k-1}\left\lfloor \frac{n}{2^i}\right\rfloor\;\le\;\sum_{i=0}^{k-1}\frac{n}{2^i}\;<\;n\sum_{i=0}^{\infty}\frac{1}{2^i}\;=\;2n.$$

除以 INCREMENT 的次數 n：amortized cost of INCREMENT = \(O(1)\)。

投影片 p.13 把上限寫成 \(i=0\) to \(k\)；位元只到 \(b_{k-1}\)，多一項不影響結論。

Aggregate method 的步驟（p.14）

  1. 找總成本（所以叫 aggregate）：super stack 是「每個元素最多被 pop 一次」，binary counter 是「\(b_i\) 翻 \(\lfloor n/2^i\rfloor\) 次」。
  2. 除以操作數：\(O(n)/n = O(1)\)。
