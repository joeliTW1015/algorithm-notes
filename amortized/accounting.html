Accounting Method 記帳法

每種操作先「收費」，收費就是它的 amortized cost。收多的錢存成 credit、綁在資料結構裡的某個物件上；之後貴的操作用這些存款付。只要銀行永遠不透支，總收費就是總實際成本的上界。

銀行帳戶的比喻（p.3–4）

  • 每個操作付一筆 amortized cost \(\hat c_i\)（投影片寫 \(\alpha_i\)），實際成本是 \(c_i\)。
  • \(\hat c_i \ge c_i\)：多的 \(\hat c_i - c_i\) 存進銀行。
  • \(\hat c_i < c_i\)：差額從存款拿。
  • 存款通常可以從資料結構「看出來」：例如 stack 裡每個元素身上都有 $1 → 存款 = 元素個數。
Lemma（p.4）如果每個操作都付得起（存款從來不是負的），那麼對任何一串操作， $$\sum_{i=1}^{n} c_i \;\le\; \sum_{i=1}^{n} \hat c_i .$$

證明：做完前 n 個操作後，銀行裡的錢 = 收到的 − 花掉的 \(=\sum_{i\le n}\hat c_i-\sum_{i\le n}c_i\)。存款 \(\ge 0\) 就是這個不等式。∎

易錯要求的是每一個時間點都不透支，不只是最後。「先少收、之後再補」不行：如果操作序列剛好在欠錢的時候停下來，那一刻的總收費就小於總實際成本，amortized cost 就不是上界了。

Super Stack（Take 2，p.5–8）

同一個 super stack（PUSH、POP、SUPER-POP(k)），這次每種操作收不同的錢：

操作實際成本 \(c\)收費 \(\hat c\)錢怎麼走
PUSH1$2$1 付 PUSH，$1 放在被 push 的元素身上
POP1$0被 pop 的元素拿出身上的 $1 付
SUPER-POP(k)k$0被 pop 的 k 個元素各捐 $1，剛好 $k

p.6 的三個問題：

  1. 誰存錢？PUSH（收 $2、只花 $1）。
  2. 誰領錢？POP 和 SUPER-POP（收 $0、實際成本 ≥ 1）。
  3. 怎麼查存款？stack 裡每個元素身上剛好有 $1 → 存款 = stack 裡的元素個數 \(\ge 0\)。

p.7：SUPER-POP(k) 要付 k，而被 pop 的 k 個元素身上正好各有 $1 → 一定付得起。所以銀行永遠不透支。

結論（p.8）PUSH 的 amortized cost = 2，POP / SUPER-POP = 0。對任何操作序列（\(n_1\) 個 PUSH、\(n_2\) 個 POP、\(n_3\) 個 SUPER-POP）， $$\text{總實際成本} \le 2n_1 + 0\cdot n_2 + 0\cdot n_3 = 2n_1 \le 2n,$$ 所以每個操作 amortized \(O(1)\)。

改收費試試：「PUSH 只收 $1」元素身上沒錢，第一次 POP 就透支（橘色）；「PUSH 收 $3」也合法，但上界變成 \(3n_1\)，比較鬆；「每個都收 $1」在 SUPER-POP(k) 時差 \(k-1\)。

觀察SUPER-POP 的實際成本是 k，amortized cost 卻是 0——amortized cost 可以跟實際成本差很多，甚至漸近地不一樣（CLRS 16.2）。重點只是總和要蓋得住。

Binary Counter（Take 2，p.9–12）

k-bit counter 從 0 開始，每次 INCREMENT 收 $2。實際成本 = 翻轉的位元數。

觀察（p.10）每次 INCREMENT 最多只有一個位元從 0 變 1（那個「第一個 0」）；其他被翻的都是從 1 變 0。
之前之後0→11→0成本
0 0 1 0 0（4）0 0 1 0 1（5）\(b_0\)—1
0 0 1 1 1（7）0 1 0 0 0（8）\(b_3\)\(b_0,b_1,b_2\)4

錢怎麼走（p.12）：

  • 收到的 $2：$1 付那個 0→1，另外 $1 存在剛變成 1 的那個位元上。
  • 每個 1→0 的位元：拿自己身上的 $1 付。
  • 所以任何時候，每個 1 身上都有 $1 → 存款 = counter 裡 1 的個數 \(\ge 0\) → 永遠付得起。

綠色 $1 是位元身上的 credit；變成 0 時那 $1 被劃掉（捐出去付翻轉）。右下圖紫線是銀行餘額，它就是 1 的個數。

「存款 = 1 的個數」的證明（p.13 整理版）

投影片 p.13 只證了 counter 是 \(0\,1\dots1\)（剛好 \(2^k-1\)）這種特殊值的情況。對每一次 INCREMENT 都成立的版本：

不變量每次 INCREMENT 之後，counter 裡每個 1 身上恰好有 $1，所以存款 \(\ge\) 1 的個數 \(\ge 0\)。
  1. Basis：count = 0，沒有 1，存款 $0。成立。
  2. Inductive step：假設做第 i 次之前成立。這次把結尾的 \(t\) 個 1 變成 0、一個 0 變成 1：
    • \(t\) 個 1→0：各用自己身上的 $1 付，付完它們變 0，身上不需要錢了。
    • 1 個 0→1：用收到的 $1 付，剩下的 $1 放在它身上。
    做完後，原本的 1 該有的錢都還在，新的 1 也有 $1。成立。
  3. 繞回的那一次（\(11\dots1 \to 00\dots0\)）：k 個 1→0 都用自己的錢付，沒有 0→1，收到的 $2 沒用到，直接留在銀行。存款 \(=\#1 + 2 \ge \#1\)。仍成立。∎
結論（p.14）INCREMENT 的 amortized cost = 2：從 0 開始做 n 次，總實際成本 \(\le 2n\)。

p.14 的問題：起始值 ≠ 0 會怎樣？

  • 上面的論證靠「每個 1 身上都有 $1」。但如果一開始 count 就不是 0，那些一開始就存在的 1 身上沒有錢——它們不是被我們收過 $2 的 INCREMENT 設成 1 的。
  • 例：從 \(00111\) 開始，第一次 INCREMENT 翻 4 個位元，只收到 $2，三個 1→0 都沒有 credit → 透支 $2。（元件裡選「p.14：從 7 = 00111 開始」，看橘色的「無」。）
  • 修法：一開始先存 \(b_0\) 元（\(b_0\) = 起始時 1 的個數），每個初始的 1 發 $1。總實際成本 \(\le 2n + b_0 \le 2n + k\)。只要 \(n=\Omega(k)\)，仍是 \(O(n)\)。
  • 用 potential method 可以算得更精確：\(\sum c_i \le 2n - b_n + b_0\)（\(b_n\) = 最後 1 的個數）。→

Accounting vs Aggregate（p.15）

Aggregate（16-1）Accounting（本頁）
怎麼算直接算 n 個操作的總成本 \(T(n)\)，除以 n先給每種操作定收費，再證明存款不會是負的
Amortized cost所有操作都一樣：\(T(n)/n\)不同操作可以不一樣（PUSH 2、POP 0）
多的錢放哪不用管綁在特定物件上，叫做該物件的 credit（stack 的元素、counter 的位元）

解題步驟

  1. 定收費：便宜但「會製造之後的工作」的操作多收一點（PUSH 製造將來的 pop，0→1 製造將來的 1→0）。
  2. 說出 credit 在哪：寫成不變量，例如「stack 裡每個元素身上有 $1」「每個 1 身上有 $1」。
  3. 逐種操作檢查：收到的錢 + 用掉的 credit ≥ 實際成本，而且做完後不變量仍成立。
  4. 收尾：credit 永遠 ≥ 0 ⇒ \(\sum c_i \le \sum \hat c_i\)，總時間就是收費總和。
