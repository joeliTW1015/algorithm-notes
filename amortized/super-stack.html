Super Stack 多重 pop

在一般 stack 上多加一個 SUPER-POP(k)。單次 SUPER-POP 可能要 \(O(n)\)，所以「n 個操作 × 每個 \(O(n)\)」得到 \(O(n^2)\)——對，但不緊。換個角度數，總成本其實只有 \(O(n)\)。

問題

朋友做了一個 super stack，除了 PUSH / POP 之外還支援：

  • SUPER-POP(k)：pop 掉頂端 k 個元素（假設 k 不超過目前 stack 大小）。
  • 成本：PUSH、POP 各 \(O(1)\)（記為 1）；SUPER-POP(k) 是 \(O(k)\)（記為 k）。
while not STACK-EMPTY(S) and k > 0
    POP(S)
    k = k - 1

從空的 stack 開始，做了 n 個操作，但不知道順序。

粗略分析：\(O(n^2)\)

  • 單次 SUPER-POP 最壞是多少？ \(O(n)\)。stack 裡最多只有 n 個元素（只有 n 個操作，最多 n 次 PUSH），所以一次最多 pop n 個。
  • n 個操作最壞總共多少？ 每個 \(O(n)\)，共 n 個 → \(O(n^2)\)。這是正確的上界，但不緊：要讓某次 SUPER-POP 很貴，前面就得先花很多次 PUSH，而那些 PUSH 本身都很便宜。

Aggregate 分析：\(O(n)\)

雖然不知道順序，還是知道：

  1. PUSH / POP 最多 n 個 → 花在它們身上的時間 \(O(n)\)。
  2. 所有 SUPER-POP 一共 pop 掉的元素個數，不會超過曾經 push 進去的元素個數——每個元素被 push 一次，最多被 pop 一次（pop 掉就不在 stack 裡了）。而 push 最多 n 次 → 花在 SUPER-POP 的時間 \(O(n)\)。
  3. 所以 n 個操作的總時間 \(= O(n)\)。更精確：總成本 \(\le \#\text{PUSH} + \#\text{被 pop 的元素} \le 2\cdot\#\text{PUSH} \le 2n\)。
結論（p.7）對任意 n、任意順序的 n 個操作，最壞總時間 \(O(n)\) ⇒ 平均每個操作 \(O(n)/n = O(1)\)。我們說每個操作的 amortized cost 是 \(O(1)\)——包括 SUPER-POP。

自己按按看：不管怎麼排，黑色的累計成本線都不會超過綠色虛線 \(2n\)。「推 19 個 + SUPER-POP(19)」那組最後一次成本 19，但前面 19 次 PUSH 各只花 1。
