Amortized vs Average-case

兩個都叫「平均」，但平均的對象完全不同：amortized 是對一串操作平均，而且那一串是最壞的；average-case 是對所有可能的輸入平均，要假設輸入的分布。

差在哪裡

Amortized analysisAverage-case analysis
平均什麼一串操作中，每個操作的成本所有輸入上，演算法的成本
需要機率嗎不需要需要假設輸入分布（例如 n! 種順序等機率）
對手最壞的操作序列也成立只對「平均的輸入」成立，壞輸入仍然可能很慢
保證n 個操作總時間 ≤ n × amortized cost（一定成立）期望值；個別一次執行可以比平均差很多
例子SUPER-POP、INCREMENT：amortized \(O(1)\)QUICKSORT：平均 \(\Theta(n\log n)\) 次比較

例：Quicksort 的平均情況（p.16–17）

  • 排序 n 個數，算 quicksort 用幾次比較。
  • 假設 n! 種輸入順序等機率出現，就可以算出這 n! 個輸入的平均比較次數：\(\Theta(n\log n)\)。
  • 所以可以說「平均排序時間 = \(\Theta(n\log n)\)」。

為什麼不能說 amortized sorting time = \(\Theta(n\log n)\)？

  1. Amortized 要對最壞的序列成立。把「排序一次」當成一個操作，考慮連續 m 次排序。對手每次都給已經排好的輸入（例如 1 2 … n），每次都要 \(n(n-1)/2=\Theta(n^2)\) 次比較。
  2. 總成本 \(\Theta(mn^2)\)，平均每次 \(\Theta(n^2)\)，不是 \(\Theta(n\log n)\)。
  3. 根本原因：quicksort 每次排序彼此獨立，一次貴的排序不會讓之後的排序變便宜。Amortized 能變便宜，靠的是「貴的操作之前一定有很多便宜的操作在『存錢』」（SUPER-POP 之前一定有 PUSH），而排序沒有這種結構。
  4. \(\Theta(n\log n)\) 只是對隨機輸入的期望值；把最壞情況加進來就沒有這個保證。∎
別搞混Randomized quicksort（隨機選 pivot）的期望時間是 \(O(n\log n)\)，對任何輸入都成立——但那是對演算法自己丟的硬幣取期望，仍然不是 amortized。
