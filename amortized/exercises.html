16.1 Aggregate analysis

16.1-1加入 MULTIPUSH，\(O(1)\) 還成立嗎？
stack 操作再加一個 MULTIPUSH(k)：一次 push k 個元素。stack 操作的 amortized cost 還是 \(O(1)\) 嗎？
詳解
  1. 不成立。MULTIPUSH(k) 的成本是 k。原本的論證靠的是「被 pop 的個數 ≤ PUSH 的次數 ≤ n」；現在一次操作就能放進 k 個元素，這個上界沒了。
  2. 反例：交替做 MULTIPUSH(k)、MULTIPOP(k)，共 n 個操作。每個都真的動到 k 個元素，總成本 \(nk\)，平均每個 \(\Theta(k)\)。k 可以跟 n 一樣大，所以 n 個操作可以到 \(\Theta(n^2)\)，不是 \(O(n)\)。
  3. 還能說什麼：被 pop 的總數 ≤ 被 push 的元素總數 = \(\sum\)（MULTIPUSH 的 k）+ #PUSH。所以總成本 ≤ 2 × 被 push 的元素總數。照 p.3 的寫法：MULTIPUSH(k) 是 amortized \(O(k)\)，PUSH、POP、MULTIPOP 是 amortized \(O(1)\)——MULTIPOP 的成本全部算到當初 push 那些元素的操作身上。
16.1-2加入 DECREMENT，n 個操作要 \(\Theta(nk)\)
在 k-bit counter 加入 DECREMENT 操作。證明 n 個操作的成本可以高達 \(\Theta(nk)\)。
詳解
  1. 上界：每個操作最多翻 k 個位元，所以永遠是 \(O(nk)\)。只要找到一串操作達到 \(\Omega(nk)\) 就是 \(\Theta(nk)\)。
  2. DECREMENT 的規則（INCREMENT 反過來）：從 \(b_0\) 往上，連續的 0 翻成 1（借位），再把第一個 1 翻成 0。在 0 上做 DECREMENT 會繞到 \(2^k-1\)（全部是 1）。
  3. 壞序列：從 0 開始，交替做 DECREMENT、INCREMENT：
    00…0 → DEC → 11…1（翻 k 個）→ INC → 00…0（翻 k 個）→ …
    每個操作都翻 k 個，n 個操作共 \(nk\)，所以是 \(\Theta(nk)\)。
  4. 不想用繞回也行：先 INCREMENT 到 \(2^{k-1}-1 = 011\dots1\)，之後交替 INCREMENT（→ \(100\dots0\)，翻 k 個）、DECREMENT（→ \(011\dots1\)，翻 k 個）。前面的 \(2^{k-1}-1\) 次是固定成本，n 夠大時總成本仍是 \(\Theta(nk)\)。
  5. 為什麼原本的論證壞掉：只有 INCREMENT 時，\(b_i\) 每 \(2^i\) 次才翻一次；有了 DECREMENT，高位元可以每次都被來回翻轉，「高位元很少翻」不再成立。
16.1-3第 i 個操作在 i 是 2 的冪時成本 i
一串 n 個操作，第 i 個操作的成本是 i（如果 i 剛好是 2 的冪），否則是 1。用 aggregate analysis 求每個操作的 amortized cost。
詳解
  1. 寫出成本：\(c_1,c_2,\dots = 1, 2, 1, 4, 1, 1, 1, 8, 1, \dots\)。單次最壞是 \(c_n\le n\)，粗略總和 \(O(n^2)\)。
  2. 分兩類加總：在 \(1..n\) 中，2 的冪是 \(1,2,4,\dots,2^{m}\)，\(m=\lfloor\lg n\rfloor\)，共 \(m+1\) 個；其他 \(n-m-1\) 個各花 1。 $$\sum_{i=1}^{n}c_i=\sum_{j=0}^{m}2^j+(n-m-1)=(2^{m+1}-1)+(n-m-1)\;<\;2n+n=3n,$$ 因為 \(2^m\le n\) ⇒ \(2^{m+1}\le 2n\)。
  3. 除以 n：amortized cost \(<3n/n=3=O(1)\)。
  4. 和 binary counter 的關係：一樣是「貴的操作很稀疏」——成本 \(2^j\) 的操作在前 n 個中只出現一次，它們的總和是等比級數，被最大的一項 \(\le n\) 主導。
