16.1 Aggregate analysis

16.1-1加入 MULTIPUSH，\(O(1)\) 還成立嗎？
stack 操作再加一個 MULTIPUSH(k)：一次 push k 個元素。stack 操作的 amortized cost 還是 \(O(1)\) 嗎？
詳解
  1. 不成立。MULTIPUSH(k) 的成本是 k。原本的論證靠的是「被 pop 的個數 ≤ PUSH 的次數 ≤ n」；現在一次操作就能放進 k 個元素，這個上界沒了。
  2. 反例：交替做 MULTIPUSH(k)、MULTIPOP(k)，共 n 個操作。每個都真的動到 k 個元素，總成本 \(nk\)，平均每個 \(\Theta(k)\)。k 可以跟 n 一樣大，所以 n 個操作可以到 \(\Theta(n^2)\)，不是 \(O(n)\)。
  3. 還能說什麼：被 pop 的總數 ≤ 被 push 的元素總數 = \(\sum\)（MULTIPUSH 的 k）+ #PUSH。所以總成本 ≤ 2 × 被 push 的元素總數。照 p.3 的寫法：MULTIPUSH(k) 是 amortized \(O(k)\)，PUSH、POP、MULTIPOP 是 amortized \(O(1)\)——MULTIPOP 的成本全部算到當初 push 那些元素的操作身上。
16.1-2加入 DECREMENT，n 個操作要 \(\Theta(nk)\)
在 k-bit counter 加入 DECREMENT 操作。證明 n 個操作的成本可以高達 \(\Theta(nk)\)。
詳解
  1. 上界：每個操作最多翻 k 個位元，所以永遠是 \(O(nk)\)。只要找到一串操作達到 \(\Omega(nk)\) 就是 \(\Theta(nk)\)。
  2. DECREMENT 的規則（INCREMENT 反過來）：從 \(b_0\) 往上，連續的 0 翻成 1（借位），再把第一個 1 翻成 0。在 0 上做 DECREMENT 會繞到 \(2^k-1\)（全部是 1）。
  3. 壞序列：從 0 開始，交替做 DECREMENT、INCREMENT：
    00…0 → DEC → 11…1（翻 k 個）→ INC → 00…0（翻 k 個）→ …
    每個操作都翻 k 個，n 個操作共 \(nk\)，所以是 \(\Theta(nk)\)。
  4. 不想用繞回也行：先 INCREMENT 到 \(2^{k-1}-1 = 011\dots1\)，之後交替 INCREMENT（→ \(100\dots0\)，翻 k 個）、DECREMENT（→ \(011\dots1\)，翻 k 個）。前面的 \(2^{k-1}-1\) 次是固定成本，n 夠大時總成本仍是 \(\Theta(nk)\)。
  5. 為什麼原本的論證壞掉：只有 INCREMENT 時，\(b_i\) 每 \(2^i\) 次才翻一次；有了 DECREMENT，高位元可以每次都被來回翻轉，「高位元很少翻」不再成立。
16.1-3第 i 個操作在 i 是 2 的冪時成本 i
一串 n 個操作，第 i 個操作的成本是 i（如果 i 剛好是 2 的冪），否則是 1。用 aggregate analysis 求每個操作的 amortized cost。
詳解
  1. 寫出成本：\(c_1,c_2,\dots = 1, 2, 1, 4, 1, 1, 1, 8, 1, \dots\)。單次最壞是 \(c_n\le n\)，粗略總和 \(O(n^2)\)。
  2. 分兩類加總：在 \(1..n\) 中，2 的冪是 \(1,2,4,\dots,2^{m}\)，\(m=\lfloor\lg n\rfloor\)，共 \(m+1\) 個；其他 \(n-m-1\) 個各花 1。 $$\sum_{i=1}^{n}c_i=\sum_{j=0}^{m}2^j+(n-m-1)=(2^{m+1}-1)+(n-m-1)\;<\;2n+n=3n,$$ 因為 \(2^m\le n\) ⇒ \(2^{m+1}\le 2n\)。
  3. 除以 n：amortized cost \(<3n/n=3=O(1)\)。
  4. 和 binary counter 的關係：一樣是「貴的操作很稀疏」——成本 \(2^j\) 的操作在前 n 個中只出現一次，它們的總和是等比級數，被最大的一項 \(\le n\) 主導。

16.2 The accounting method

16.2-1每 k 個操作備份一次的 stack
對一個大小永遠不超過 k 的 stack 做 PUSH、POP。每做完 k 個操作，就自動把整個 stack 複製一份備份。用 accounting method 指定適當的 amortized cost，證明 n 個操作（包含複製）的總成本是 \(O(n)\)。
詳解
  1. 實際成本：PUSH、POP 各 1；一次備份要複製目前 stack 裡的每個元素，成本 = stack 大小 \(\le k\)。
  2. 收費：PUSH、POP 都收 $2：$1 付自己，$1 存進「備份基金」。
  3. 為什麼夠：兩次備份之間剛好有 k 個操作，基金多了 $k。備份時 stack 大小 \(\le k\)，所以 $k 一定付得起。付完後基金仍 \(\ge 0\)（多的留著）。
    不變量：第 j 個操作之後，基金 \(\ge j \bmod k\ge 0\)。
  4. 結論：credit 永遠 \(\ge 0\) ⇒ 總實際成本 \(\le\sum\hat c_i=2n=O(n)\)。
  5. 重點是「操作數」而不是「PUSH 數」：備份是每 k 個操作發生一次，所以讓每個操作都存 $1 最直接。如果只讓 PUSH 存錢，要存 $2 才夠（PUSH 收 $3）：兩次備份間若有 p 個 PUSH、\(k-p\) 個 POP，備份時的大小 \(\le s_{ ext{前}}+p-(k-p)\le 2p\)。
16.2-3Counter 加上 RESET，n 個操作仍是 \(O(n)\)
counter 除了 INCREMENT，還要能 RESET（所有位元歸零）。檢查或修改一個位元算 \(\Theta(1)\)。說明怎麼用位元陣列實作，讓從 0 開始的任意 n 個 INCREMENT / RESET 總共 \(O(n)\) 時間。（提示：記住最高位的 1 在哪。）
詳解
  1. 問題在哪：直接把 k 個位元全部清 0，RESET 就是 \(\Theta(k)\)；n 個 RESET 是 \(\Theta(nk)\)。可是位元 \(b_{\max+1}\) 以上本來就都是 0，不用碰。
  2. 實作：多存一個 max = 最高位的 1 的位置（全部是 0 時為 −1）。 
    i = 0
while i < k and A[i] == 1
    A[i] = 0
    i = i + 1
if i < k
    A[i] = 1
    if i > max then max = i
else max = -1            // 繞回 0

    for i = 0 to max         // 只清到最高位的 1
    A[i] = 0
max = -1
  3. 收費：INCREMENT 收 $3，RESET 收 $1（付 max 這類 \(O(1)\) 的雜事）。INCREMENT 的 $3：
    • $1 付那個 0→1；
    • $1 放在剛變成 1 的位元上，付它之後變回 0（被 INCREMENT 或被 RESET）；
    • $1 存進「RESET 基金」。
  4. RESET 為什麼付得起：RESET 碰 \(b_0..b_{\max}\)，共 \(\max+1\) 個位元。上一次歸零（RESET 或繞回）之後，count 從 0 長到至少 \(2^{\max}\)，所以至少做了 \(2^{\max}\ge\max+1\) 次 INCREMENT，基金至少 $(max+1)。
  5. 寫成不變量（也就是 potential \(\Phi=\#1+(\max+1)\)）：銀行 \(\ge \#1 + (\max+1)\)。
    • INCREMENT（翻掉 t 個 1、設一個 0）：銀行 \(+3-(t+1)=2-t\)；#1 變化 \(1-t\)，max 最多加 1。右邊最多加 \(2-t\)。✓
    • 繞回：銀行 \(+3-k\)；右邊從 \(k+k\) 掉到 0，掉了 \(2k\)。✓
    • RESET：銀行 \(+1-(\max+1)\)；右邊掉到 0，掉了 \(\#1+\max+1\ge\max+1\)。✓
  6. 結論：銀行永遠 \(\ge 0\) ⇒ 總時間 \(\le 3\cdot\#\text{INC}+\#\text{RESET}\le 3n=O(n)\)。

16.3 The potential method

16.3-1\(\Phi(D_0)\ne0\) 時換成從 0 開始的 \(\Phi'\)
假設 \(\Phi(D_i)\ge\Phi(D_0)\) 對所有 i 成立，但 \(\Phi(D_0)\ne0\)。證明存在 \(\Phi'\) 使得 \(\Phi'(D_0)=0\)、\(\Phi'(D_i)\ge0\)（\(i\ge1\)），而且用 \(\Phi'\) 算出的 amortized cost 跟用 \(\Phi\) 的一樣。
詳解
  1. 定義 \(\Phi'(D)=\Phi(D)-\Phi(D_0)\)：整個位能往下平移一個常數。
  2. \(\Phi'(D_0)=\Phi(D_0)-\Phi(D_0)=0\)。
  3. \(\Phi'(D_i)=\Phi(D_i)-\Phi(D_0)\ge0\)，因為題目給了 \(\Phi(D_i)\ge\Phi(D_0)\)。
  4. amortized cost 不變：常數在相減時消掉 $$\hat c_i'=c_i+\Phi'(D_i)-\Phi'(D_{i-1})=c_i+\bigl(\Phi(D_i)-\Phi(D_0)\bigr)-\bigl(\Phi(D_{i-1})-\Phi(D_0)\bigr)=\hat c_i.\;\blacksquare$$
  5. 直覺：跟物理一樣，位能的「零點」可以隨便選，只有差有意義。
16.3-3Min-heap：INSERT \(O(\lg n)\)、EXTRACT-MIN \(O(1)\)
一般的 binary min-heap，INSERT 和 EXTRACT-MIN 最壞都是 \(O(\lg n)\)（n = 目前 heap 裡的個數）。給一個 potential function \(\Phi\)，讓 INSERT 的 amortized cost 是 \(O(\lg n)\)、EXTRACT-MIN 是 \(O(1)\)，並證明。注意：不知道 heap 最多會有幾個元素。
詳解
  1. 想法：每個元素被 INSERT 時多付一筆「將來把它 EXTRACT 掉」的錢。EXTRACT 一次最多 \(O(\lg n)\)，所以 INSERT 多付 \(O(\lg n)\) 就夠——但 n 會變，所以位能要跟目前的 n 有關，不能用最大值。
  2. 實際成本：存在常數 c，使大小為 n 時兩種操作都 \(\le c(1+\lg n)\)（INSERT 的 n 是插入後、EXTRACT-MIN 的 n 是取出前）。
  3. 位能： $$\Phi(D)=c\sum_{j=1}^{n}\lg j=c\lg(n!)\qquad(n=D\text{ 的大小}).$$ 空 heap：\(\Phi(D_0)=0\)；\(\lg j\ge0\) ⇒ \(\Phi\ge0\)。合法。
  4. INSERT（\(n-1\to n\)）：\(\Delta\Phi=c\lg n\)， $$\hat c\le c(1+\lg n)+c\lg n=c(1+2\lg n)=O(\lg n).$$
  5. EXTRACT-MIN（\(n\to n-1\)）：\(\Delta\Phi=-c\lg n\)， $$\hat c\le c(1+\lg n)-c\lg n=c=O(1).$$
  6. 結論：\(\Phi(D_i)\ge\Phi(D_0)\) ⇒ 總實際成本 ≤ 總 amortized cost。∎
  7. 別的選擇：\(\Phi=c\,n\lg n\) 也行（\(n\lg n-(n-1)\lg(n-1)\) 介於 \(\lg n\) 和 \(\lg n+\lg e\) 之間），只是算起來比 \(\lg(n!)\) 麻煩。

元件裡實際成本取 1 + 交換次數（\(\le 1+\lfloor\lg n\rfloor\)，c = 1）。看 EXTRACT-MIN 那幾步的 \(\hat c\)：永遠 \(\le 1\)。

16.3-4Stack 一開始有 \(s_0\) 個，最後 \(s_n\) 個
做 n 個 PUSH / POP / MULTIPOP，stack 一開始有 \(s_0\) 個元素、最後有 \(s_n\) 個。總成本是多少？
詳解
  1. 位能：還是 \(\Phi\) = stack 裡的元素個數，只是現在 \(\Phi(D_0)=s_0\)、\(\Phi(D_n)=s_n\)。amortized cost 跟以前一樣：PUSH 2、POP 0、MULTIPOP 0。
  2. 用 telescoping 等式（不需要 \(\Phi(D_i)\ge\Phi(D_0)\)）： $$\sum_{i=1}^{n}c_i=\sum_{i=1}^{n}\hat c_i-\Phi(D_n)+\Phi(D_0)=2\cdot\#\text{PUSH}-s_n+s_0\;\le\;2n-s_n+s_0.$$
  3. 直接數也一樣：被 pop 的個數 = \(s_0+\#\text{PUSH}-s_n\)，總成本 = #PUSH + 被 pop 的個數 = \(2\cdot\#\text{PUSH}+s_0-s_n\)。
  4. 為什麼不能套用「\(\Phi(D_i)\ge\Phi(D_0)\)」：MULTIPOP 可以把原本的 \(s_0\) 個也 pop 掉，讓 \(\Phi(D_i)<s_0\)。那些元素是「免費送的」，沒有人替它們存過錢，所以要在總成本裡多加 \(s_0\)。
16.3-5用兩個 stack 做 queue
用兩個普通的 stack 實作 queue，讓 ENQUEUE 和 DEQUEUE 的 amortized cost 都是 \(O(1)\)。
詳解
  1. 實作：IN 收新元素，OUT 負責出隊。 
    ENQUEUE(Q, x)
    PUSH(IN, x)
DEQUEUE(Q)
    if STACK-EMPTY(OUT)
        while not STACK-EMPTY(IN)
            PUSH(OUT, POP(IN))     // 倒過來：最舊的到 OUT 頂端
    return POP(OUT)
  2. 順序對：IN 倒進 OUT 時順序反轉，最早進來的在 OUT 最上面；OUT 裡的元素都比 IN 裡的舊，所以先清空 OUT 再倒是對的 FIFO。
  3. 實際成本（每個 PUSH / POP 算 1）：ENQUEUE = 1；DEQUEUE = 1，或在 OUT 空時要先倒 m 個 = \(2m+1\)。最壞單次 \(\Theta(n)\)。
  4. 位能 \(\Phi=2\cdot|IN|\)（IN 裡每個元素將來要被 pop 一次、push 一次）。\(\Phi(D_0)=0\)、\(\Phi\ge0\)。
    • ENQUEUE：\(\hat c=1+2=3\)。
    • DEQUEUE 不用倒：\(\hat c=1+0=1\)。
    • DEQUEUE 要倒 m 個：\(\hat c=(2m+1)+(0-2m)=1\)。
  5. 結論：兩種操作 amortized 都是 \(O(1)\)。Accounting 的說法：每個元素 ENQUEUE 時付 $3（push 進 IN、之後 pop 出 IN、push 進 OUT），DEQUEUE 付最後那次 pop 的 $1。
16.3-6INSERT 與 DELETE-LARGER-HALF
設計一個資料結構存整數 multiset S（可以重複），支援 INSERT(S, x) 和 DELETE-LARGER-HALF(S)（刪掉最大的 \(\lceil|S|/2\rceil\) 個）。任意 m 個操作要 \(O(m)\) 時間，而且能在 \(O(|S|)\) 時間輸出 S 的所有元素。
詳解
  1. 資料結構：一個沒排序的陣列（dynamic array 或 linked list）。
    • INSERT：接到尾端，\(O(1)\)。
    • DELETE-LARGER-HALF：令 \(s=|S|\)、\(h=\lceil s/2\rceil\)。用 Ch9 的 linear-time SELECT 找第 h 大的元素 y（\(O(s)\)）；掃一次，留下比 y 小的，以及剛好補足 \(s-h\) 個的 y（處理重複值），其餘刪掉。總共 \(O(s)\)。
    • 輸出：掃一次陣列，\(O(|S|)\)。
  2. 實際成本：存在常數 c，INSERT \(\le c\)，DELETE-LARGER-HALF \(\le c\cdot s\)。
  3. 位能 \(\Phi=2c\cdot|S|\)，\(\Phi(D_0)=0\)、\(\Phi\ge0\)。
    • INSERT：\(\hat c\le c+2c=3c\)。
    • DELETE-LARGER-HALF：|S| 少了 \(h\ge s/2\)，\(\Delta\Phi\le-2c\cdot s/2=-cs\)，\(\hat c\le cs-cs=0\)。
  4. 結論：m 個操作總時間 \(\le 3c\cdot m=O(m)\)。∎
  5. 易錯：用排序找中位數是 \(O(s\lg s)\)，\(\Delta\Phi\) 抵不掉，會變成 \(O(m\lg m)\)。一定要 linear-time SELECT。

元件裡把常數 c 取 1：INSERT 成本 1、DELETE-LARGER-HALF 成本 |S|。
