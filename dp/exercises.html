14.1 Rod cutting

14.1-2「密度優先」的貪婪法不一定最佳
定義長度 \(i\) 的密度為 \(p_i/i\)。貪婪策略：每次切下密度最大的那一段（長度 \(i\le\) 剩餘長度），剩下的繼續用同樣策略。舉反例說明它不一定最佳。
詳解

不一定最佳，反例如下。

\(i\)1234
\(p_i\)1203336
\(p_i/i\)110119

\(n=4\)。Greedy：先切密度最大的 \(3\)，剩 \(1\) → \(33+1=34\)。
Optimal：\(2+2\) → \(20+20=40>34\)。∎

14.1-3每切一刀有固定成本 c
每切一刀要付固定成本 \(c\)，收益 = 各段價格總和 − 刀費。設計這個變形的 DP 演算法。
詳解

\(r_0=0,\quad r_j=\max\Bigl(p_j,\ \max_{1\le i\lt j}\{p_i+r_{j-i}-c\}\Bigr)\)，時間 \(\Theta(n^2)\)。

Idea第一段長 \(i\)：\(i=j\) 是不切，沒有刀費；\(i<j\) 切一刀扣 \(c\)，剩下 \(j-i\) 的刀費已含在 \(r_{j-i}\)。

let r[0:n] be a new array
r[0] = 0
for j = 1 to n
    q = p[j]                          // 不切：沒有刀費
    for i = 1 to j - 1
        q = max(q, p[i] + r[j - i] - c)   // 切一刀：扣 c
    r[j] = q
return r[n]

Time內圈跑 \(j-1\) 次，\(\sum_{j=1}^{n}(j-1)=\frac{n(n-1)}{2}=\Theta(n^2)\)。

易錯：寫成 \(\max_{1\le i\le j}\{p_i+r_{j-i}\}-c\) 會連「不切」也扣刀費。

14.1-4迴圈只跑到 ⌊n/2⌋
把 CUT-ROD 和 MEMOIZED-CUT-ROD-AUX 的 for 迴圈改成只跑到 \(\lfloor n/2\rfloor\)。還需要改什麼？執行時間有什麼影響？
詳解

要改兩處：(1) \(p_i\) 改成 \(r_i\)（左段也能再切）；(2) 「不切」\(p_n\) 另外處理。CUT-ROD 仍是指數時間，MEMOIZED 仍是 \(\Theta(n^2)\)。

Why\(r_n=\max\bigl(p_n,\ \max_{1\le i\le\lfloor n/2\rfloor}(r_i+r_{n-i})\bigr)\)：\(r_i+r_{n-i}\) 和 \(r_{n-i}+r_i\) 相同，試一半就夠；但 \(i=n\)（不切）不在迴圈內。

if n == 0
    return 0
q = p[n]                              // 不切
for i = 1 to ⌊n/2⌋
    q = max(q, CUT-ROD-HALF(p, i) + CUT-ROD-HALF(p, n - i))   // 兩段都可再切
return q

CUT-ROD呼叫次數 \(T(n)\ge1+\sum_{j=1}^{n-1}T(j)\)（\(i\) 和 \(n-i\) 涵蓋 \(1..n-1\)），\(T(1)=1\) ⇒ \(T(n)\ge2^{n-1}\)，仍是指數。

MEMOIZED每個 \(r_j\) 只算一次，每次 \(\lfloor j/2\rfloor\) 圈：\(\sum_{j=1}^{n}\lfloor j/2\rfloor=\Theta(n^2)\)，只差常數。

14.1-6Fibonacci 的 O(n) DP 與 subproblem graph
給一個 \(O(n)\) 的 DP 演算法計算第 \(n\) 個 Fibonacci 數（\(F_0=0, F_1=1, F_i=F_{i-1}+F_{i-2}\)）。畫出 subproblem graph，它有幾個頂點、幾條邊？
詳解

Bottom-up \(O(n)\)；subproblem graph 有 \(n+1\) 個頂點、\(2(n-1)\) 條邊（\(n\ge1\)）。

if n ≤ 1
    return n
let f[0:n] be a new array
f[0] = 0;  f[1] = 1
for i = 2 to n
    f[i] = f[i - 1] + f[i - 2]        // 子問題已算好，O(1)
return f[n]

Time迴圈 \(n-1\) 次，每次 \(O(1)\) → \(O(n)\)。

Graph頂點 \(F_0,\dots,F_n\)，共 \(n+1\) 個；每個 \(F_i\ (i\ge2)\) 連到 \(F_{i-1}, F_{i-2}\)，共 \(2(n-1)\) 條邊。

14.2-3用 substitution method 證明 Ω(2ⁿ)
證明括號方式數的遞迴式 \(P(n)=\sum_{k=1}^{n-1}P(k)P(n-k)\)（\(P(1)=1\)）的解是 \(\Omega(2^n)\)。
詳解

Claim：\(P(n)\ge2^{n-2}\) for all \(n\ge2\) ⇒ \(P(n)=\Omega(2^n)\)（\(c=\tfrac14,\ n_0=2\)）。

Base\(P(2)=P(1)P(1)=1=2^0\).

StepAssume \(P(m)\ge2^{m-2}\) for \(2\le m\lt n\) (\(n\ge3\)). All terms are \(\ge0\); keep only \(k=1\) and \(k=n-1\): $$P(n)\ge P(1)P(n-1)+P(n-1)P(1)=2P(n-1)\ge2\cdot2^{n-3}=2^{n-2}.$$

Hence \(P(n)\ge\tfrac14\cdot2^n\) for all \(n\ge2\), i.e. \(P(n)=\Omega(2^n)\). ∎

投影片把同一招用在 RECURSIVE-MATRIX-CHAIN 的 \(T(n)\ge2^{n-1}\)，見 Matrix-Chain 頁。

14.2-5表格被讀取的總次數 = (n³ − n)/3
令 \(R(i,j)\) 為 MATRIX-CHAIN-ORDER 計算其他格子時讀取 \(m[i,j]\) 的次數。證明 \(\sum_{i=1}^{n}\sum_{j=i}^{n}R(i,j)=\dfrac{n^3-n}{3}\)。
詳解

Idea改數「每格計算時讀了幾格」。算長度 \(l\) 的 \(m[i,j]\)：\(k=i..j-1\) 共 \(l-1\) 圈，每圈讀 \(m[i,k], m[k+1,j]\) → \(2(l-1)\) 次；長度 \(l\) 的格子有 \(n-l+1\) 個。

$$\begin{aligned} \sum R(i,j)&=\sum_{l=2}^{n}(n-l+1)\cdot2(l-1)=2\sum_{t=1}^{n-1}(n-t)\,t\qquad(t=l-1)\\ &=2\Bigl[n\cdot\frac{(n-1)n}{2}-\frac{(n-1)n(2n-1)}{6}\Bigr] =\frac{n(n-1)(n+1)}{3}=\frac{n^3-n}{3}.\ ∎ \end{aligned}$$

14.3 Elements of dynamic programming

14.3-2Merge sort 的遞迴樹：memoization 沒用
畫出 MERGE-SORT 在 16 個元素的陣列上的遞迴樹，解釋為什麼 memoization 無法加速像 merge sort 這樣好的 divide-and-conquer 演算法。
詳解

Merge sort 沒有 overlapping subproblems，查表永遠查不到，memoization 無法加速。

Tree根 \(A[1..16]\) → \([1..8],[9..16]\) → 4 個長 4 → 8 個長 2 → 16 個長 1，共 31 個節點（樹形見下方元件）。

Why31 個節點是 31 個不同的區間 \(A[p..r]\)，每個子問題只出現一次。Memoization 只在同一子問題被問第二次時省時間，這裡只會多花記憶體。

14.3-3改成「最多」乘法次數，還有 optimal substructure 嗎？
矩陣鏈乘的反向版本：加括號使純量乘法次數最多。這個問題有 optimal substructure 嗎？
詳解

有。\(m[i,j]=\max_{i\le k\lt j}\{m[i,k]+m[k+1,j]+p_{i-1}p_kp_j\}\)。

Proof設 \(A_i..A_j\) 的最大成本括號最後切在 \(k\)，成本 = 左半成本 + 右半成本 + \(p_{i-1}p_kp_j\)。最後一項只和 \(i,k,j\) 有關，左右兩半用不同的矩陣，互不影響（子問題獨立）。 若左半不是最大成本的括號，換成更大的，總成本變大，矛盾；右半同理（cut-and-paste）。∎

對比最長簡單路徑：那裡的兩個子問題會搶同一批頂點，所以沒有 optimal substructure。

14.3-4先選 k 再解子問題的貪婪法
有人主張不用解完所有子問題：在 \(A_i\cdots A_j\) 中，直接選讓 \(p_{i-1}p_kp_j\) 最小的 \(k\) 當分割點，再遞迴處理兩邊。找一個讓這個貪婪法得到非最佳解的例子。
詳解

反例：\(\langle1,2,3,4\rangle\)，即 \(A_1:1\times2,\ A_2:2\times3,\ A_3:3\times4\)。

Greedy\(k=1\)：\(p_0p_1p_3=8\)；\(k=2\)：\(p_0p_2p_3=12\) → 選 \(k=1\)，\(A_1(A_2A_3)\)：\(2\cdot3\cdot4+8=32\)。
Optimal\((A_1A_2)A_3\)：\(1\cdot2\cdot3+1\cdot3\cdot4=18<32\)。∎

原因：只看最後一次相乘的成本，忽略了子問題的成本。

14.3-5限量的鋼條：optimal substructure 失效
鋼條切割加上限制：長度 \(i\) 的段最多只能切出 \(l_i\) 段。說明 14.1 節的 optimal substructure 不再成立。
詳解

不成立：子問題不再獨立——第一段用掉了長度 \(i\) 的名額，剩下 \(n-i\) 的最佳解可能也要用長度 \(i\)。

Example\(p_1..p_4=1,5,5,6\)，\(l_2=1\)（長度 2 最多一段），\(n=4\)。

  • 合法切法：\(4\to6\)、\(3+1\to6\)、\(2+1+1\to\mathbf{7}\)、\(1\times4\to4\)（\(2+2\) 違反 \(l_2\)）。最佳 = 7。
  • 最佳解切掉第一段 2 後，剩下的 2 是 \(1+1\)（2 元），但長 2 單獨的最佳解是不切（5 元）。
  • 想用 cut-and-paste 換成 \(r_2=5\) → 得到 \(2+2\)，不合法。

所以「最佳解包含子問題的最佳解」不成立，\(r_j\) 這個狀態不夠，還要記剩下的名額。∎

14.4 Longest common subsequence

14.4-2不用 b 表，在 O(m + n) 時間印出 LCS
只用完成的 \(c\) 表和原本的 \(X, Y\)（不用 \(b\) 表），在 \(O(m+n)\) 時間重建一個 LCS。
詳解

Idea\(b[i,j]\) 的方向可以在 \(O(1)\) 時間由 \(x_i, y_j\) 和 \(c\) 表重新判斷（和 LCS-LENGTH 的條件相同）。

if i == 0 or j == 0
    return
if x_i == y_j                          // 原本的 "↖"
    PRINT-LCS-NO-B(c, X, Y, i - 1, j - 1)
    print x_i
elseif c[i - 1, j] ≥ c[i, j - 1]       // 原本的 "↑"
    PRINT-LCS-NO-B(c, X, Y, i - 1, j)
else                                   // 原本的 "←"
    PRINT-LCS-NO-B(c, X, Y, i, j - 1)

Time每次呼叫 \(i\) 或 \(j\) 至少減 1，最多 \(m+n\) 次，每次 \(O(1)\) → \(O(m+n)\)。

14.4-3Memoized 版本的 LCS-LENGTH
寫出 \(O(mn)\) 的 memoized LCS-LENGTH。
詳解
m = X.length;  n = Y.length
let c[0:m, 0:n] be a new table
for i = 0 to m
    for j = 0 to n
        c[i, j] = -1          // -1 = 還沒算
return LOOKUP-LCS(c, X, Y, m, n)

if c[i, j] > -1               // 算過了，直接查表
    return c[i, j]
if i == 0 or j == 0
    c[i, j] = 0
elseif x_i == y_j
    c[i, j] = LOOKUP-LCS(c, X, Y, i-1, j-1) + 1
else c[i, j] = max(LOOKUP-LCS(c, X, Y, i-1, j),
                   LOOKUP-LCS(c, X, Y, i, j-1))
return c[i, j]

Time初始化 \(\Theta(mn)\)。每格最多真的計算一次，計算時最多發出 2 個呼叫 → 總呼叫數 \(\le1+2(m+1)(n+1)\)，每次 \(O(1)\) → \(O(mn)\)。

14.4-5O(n²) 的最長遞增子序列
給 \(O(n^2)\) 演算法，找 \(n\) 個數的序列中最長的 monotonically increasing subsequence。
詳解

Idea\(L[i]\) = 以 \(A[i]\) 結尾的最長子序列長度（monotonically increasing 允許相等）： $$L[i]=1+\max\bigl(\{0\}\cup\{L[j]: j\lt i,\ A[j]\le A[i]\}\bigr),\qquad \text{answer}=\max_i L[i].$$

for i = 1 to n
    L[i] = 1;  prev[i] = NIL               // 只有 A[i] 自己
    for j = 1 to i - 1
        if A[j] ≤ A[i] and L[j] + 1 > L[i]   // 接在 A[j] 後面更長
            L[i] = L[j] + 1;  prev[i] = j
best = argmax_i L[i]
// 從 best 沿 prev 往回走，倒過來印出

Time雙層迴圈 \(\sum_{i}(i-1)=\Theta(n^2)\)；回溯 \(O(n)\)。總共 \(\Theta(n^2)\)。

另解：\(A'\) = 排序後的 \(A\)，答案 = LCS\((A, A')\)，也是 \(O(n^2)\)。

14.5-3不存 w 表，每次直接加總
如果不維護 \(w[i,j]\) 表，而是在第 9 行用定義 \(w(i,j)=\sum_{l=i}^{j}p_l+\sum_{l=i-1}^{j}q_l\) 直接算，OPTIMAL-BST 的漸近時間會改變嗎？
詳解

不會，仍是 \(\Theta(n^3)\)。

Why直接加總 \(w(i,j)\) 要 \(\Theta(l)\)（\(l=j-i+1\)）。第 9 行在 \(r\) 迴圈外，每個 \((i,j)\) 只做一次： $$\sum_{l=1}^{n}(n-l+1)\cdot\Theta(l)=\Theta(n^3).$$ 原本 \(r\) 迴圈就是 \(\Theta(n^3)\)，總共 \(\Theta(n^3)+\Theta(n^3)=\Theta(n^3)\)，只有常數變大。

易錯：若把加總放進 \(r\) 迴圈（每試一個 root 重算一次），就變成 \(\Theta(n^4)\)。
