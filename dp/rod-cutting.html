Lecture 14-1 · Dynamic Programming I

Rod Cutting 鋼條切割

用一個最簡單的最佳化問題，把 DP 的整套流程走一遍：先寫出遞迴式、發現它慢得離譜、找出原因（重複子問題），再用一張表把它變成 \(\Theta(n^2)\)。

DP 是什麼？

  • Divide-and-conquer：把大問題拆成互不重疊的小問題各自解決（例如 merge sort）。
  • Dynamic programming：也是拆成小問題，但小問題之間會重疊——同一個子問題會被需要很多次。DP 的做法是每個子問題只解一次，把答案存進表格，之後直接查。
  • DP 不是某一個演算法，而是一種技巧（跟 divide-and-conquer 一樣）。
  • 名字裡的 “programming” 是早年「tabular method（填表法）」的意思，跟 linear programming 的 programming 同義，不是寫程式。
  • DP 通常用在 optimization problems：在很多可行解中找一個值最佳（最大或最小）的解。這一章兩種都會看到：rod cutting 是最大化、matrix-chain 和 optimal BST 是最小化。

問題定義

一根長 \(n\) 吋的鋼條，可以切成整數吋的小段（切割免費），每段依長度 \(i\) 賣 \(p_i\) 元。怎麼切收益最大？

  • Input：長度 \(n\)，價格表 \(p_1, p_2, \dots, p_n\)。
  • Output：最大收益 \(r_n\)＝各段價格總和的最大值（各段長度加起來要等於 \(n\)）。
長度 \(i\)12345678910
價格 \(p_i\)1589101717202430

如果 \(p_n\) 夠大，最佳解可能是完全不切（例如 \(n=6\) 時直接賣 17 最好）。

暴力法：有 \(2^{n-1}\) 種切法

長度 \(n\) 的鋼條有 \(n-1\) 個「1 吋刻度」，每個刻度都能選擇切或不切，所以總共 \(2^{n-1}\) 種切法。\(n=4\) 時有 8 種，最好的是切成 2+2，收益 \(p_2+p_2=10\)。

用肉眼檢查前幾個長度，可以得到最佳收益 \(r_i\)：

\(i\)\(r_i\)最佳切法
111（不切）
252（不切）
383（不切）
4102 + 2
5132 + 3
6176（不切）
7181 + 6 或 2 + 2 + 3
8222 + 6

指數級的枚舉在 \(n\) 稍大時就不可行，我們需要更聰明的方法。

寫出遞迴式

拆法一：切成兩段，兩段都用最佳解

最佳解要嘛不切（收益 \(p_n\)），要嘛在某處切一刀分成長 \(i\) 和 \(n-i\) 的兩段，兩段各自再用最佳切法：

$$r_n=\max\{\,p_n,\; r_1+r_{n-1},\; r_2+r_{n-2},\; \dots,\; r_{n-1}+r_1\,\}$$

這樣每個選擇會產生兩個子問題。

拆法二（比較簡單）：只看最左邊那一刀

任何一種切法都有「最左邊的一段」。假設它長 \(i\)：這一段不再切，直接賣 \(p_i\)；右邊剩下的長 \(n-i\) 那段才繼續用最佳切法。

$$r_n=\max_{1\le i\le n}\{\,p_i + r_{n-i}\,\},\qquad r_0 = 0$$
  • \(i=n\) 的情況就是「不切」：\(p_n + r_0 = p_n\)。
  • 每個選擇只剩一個子問題 \(r_{n-i}\)，比拆法一乾淨。後面的程式都用這個式子。

Optimal substructure

要解大小 \(n\) 的問題，只要解更小的子問題。切一刀之後剩下的部分，在最佳解中一定也是用最佳方式切的——否則把那部分換成更好的切法，整體收益會更高，矛盾（這叫 cut-and-paste 論證）。子問題之間彼此獨立，可以分開解。

直接遞迴：CUT-ROD

if n == 0
    return 0
q = -∞
for i = 1 to n
    q = max{q, p[i] + CUT-ROD(p, n - i)}
return q

這個程式是對的，但非常慢：\(n=40\) 可能要跑超過一小時，而且 \(n\) 每加 1，時間大約變兩倍。原因是 CUT-ROD 一直重算已經算過的子問題。拉動下面的 \(n\)，看看遞迴樹長多大：

證明 \(T(n)=2^n\)（投影片上的 Exercise）

令 \(T(n)\) 為呼叫 CUT-ROD(p, n) 時，總共發生的呼叫次數（包含自己）。

$$T(n)=\begin{cases}1 & n=0\\[2pt] 1+\displaystyle\sum_{j=0}^{n-1}T(j) & n\ge 1\end{cases}$$
  1. 式子從哪來：「1」是這次呼叫本身；迴圈 \(i=1\dots n\) 分別呼叫 CUT-ROD(p, n−i)，也就是參數 \(j=n-i\) 跑過 \(0,1,\dots,n-1\) 各一次。
  2. Base case：\(T(0)=1=2^0\) ✓。
  3. Induction：假設 \(T(j)=2^j\) 對所有 \(j<n\) 成立，則 $$T(n)=1+\sum_{j=0}^{n-1}2^j = 1+(2^n-1)=2^n.$$ （等比級數 \(1+2+\dots+2^{n-1}=2^n-1\)。）
  4. 結論：呼叫次數是 \(2^n\)，執行時間是指數級。上面的互動圖中節點總數正好是 \(2^n\)。
另一種看法遞迴樹的每個「從根走到某節點的路徑」對應到一種切法的前綴，所以樹的葉子數 = \(2^{n-1}\) = 所有切法數，直接遞迴等於把所有切法都試過一遍。

DP 解法：Store, don't recompute

  • 每個子問題只解一次，把答案存在表中，再遇到時直接查表。
  • 這是 time-memory trade-off：多花記憶體，換來把指數時間降成多項式時間。
  • 兩種寫法：top-down with memoization、bottom-up。

1. Top-down with memoization

let r[0:n] be a new array   // 存答案
for i = 0 to n
    r[i] = -∞               // -∞ 代表「還沒算」
return MEMOIZED-CUT-ROD-AUX(p, n, r)

if r[n] >= 0                // 算過了？
    return r[n]             // 直接查表
if n == 0
    q = 0
else q = -∞
    for i = 1 to n
        q = max{q, p[i] + MEMOIZED-CUT-ROD-AUX(p, n - i, r)}
r[n] = q                    // 存起來
return q

保留原本遞迴的寫法，只是在「算之前先查表、算完存表」。

2. Bottom-up

let r[0:n] be a new array
r[0] = 0
for j = 1 to n              // 長度由小到大
    q = -∞
    for i = 1 to j          // 第一刀的位置
        q = max{q, p[i] + r[j - i]}
    r[j] = q
return r[n]

按照子問題的大小由小到大解。算 \(r[j]\) 時，它需要的 \(r[0..j-1]\) 都已經在表裡了。

執行時間：兩者都是 \(\Theta(n^2)\)

  • Bottom-up：雙層迴圈，內層跑 \(j\) 次，總共 \(\sum_{j=1}^{n} j = n(n+1)/2 = \Theta(n^2)\)。
  • Top-down：每個 \(r[n']\) 只會真的計算一次，計算 \(r[n']\) 時迴圈跑 \(n'\) 次，加總一樣是 \(\Theta(n^2)\)。

Subproblem graph

  • 把遞迴樹中代表同一個子問題的節點全部合併成一個頂點，邊從 parent 指向 child，就是 subproblem graph（上面互動圖的右半部）。
  • 頂點數 = 子問題數；計算一個子問題的時間通常和它的 out-degree（出邊數＝選擇數）成正比。
  • 所以 DP 總時間通常 ≈ 頂點數 + 邊數。Rod cutting：\(n+1\) 個頂點、\(n(n+1)/2\) 條邊 → \(\Theta(n^2)\)。
  • Bottom-up 的計算順序就是 subproblem graph 的 reverse topological order（先算沒有出邊的子問題）。

記錄選擇：EXTENDED-BOTTOM-UP-CUT-ROD

只知道最大收益還不夠，我們也想知道怎麼切。做法是多開一個表 \(s[j]\)，記下長度 \(j\) 的最佳第一刀長度，最後再用另一個程序把切法印出來。按 ▶ 一步步看（鍵盤 ← → 也可以）：

(r, s) = EXTENDED-BOTTOM-UP-CUT-ROD(p, n)
while n > 0
    print s[n]              // 印出第一段的長度
    n = n - s[n]            // 剩下的部分繼續查

以投影片的價格為例，最後的表：

\(i\)012345678
\(r[i]\)01581013171822
\(s[i]\)12322612

例如 \(n=7\)：\(s[7]=1\) → 切下 1，剩 6；\(s[6]=6\) → 整段賣。答案 1 + 6，收益 18。

什麼問題適合 DP？

重點
  1. Optimal substructure（讓我們能寫出遞迴式）：問題的最佳解裡包含子問題的最佳解。
  2. Overlapping subproblems（讓我們能加速）：遞迴演算法會一再遇到同一個子問題。

只有 1 沒有 2：用 divide-and-conquer 就好（例如 merge sort，見習題 14.3-2）。只有 2 沒有 1：根本寫不出正確的遞迴式（見最長簡單路徑）。
