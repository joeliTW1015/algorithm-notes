Lecture 14-2 · Elements of dynamic programming

何時該用 DP？

看過 rod cutting 和 matrix-chain 之後，把共通點抽出來：一個問題要同時具備兩個性質，DP 才會又對又快。這一頁也說明一個常見陷阱——看起來像 DP、其實不是的問題。

兩大性質

重點
  1. Optimal substructure：問題的最佳解包含子問題的最佳解。（有它才能寫出遞迴式；例：matrix-chain。）
  2. Overlapping subproblems：遞迴演算法會一再遇到同一個子問題。（有它 DP 才有加速效果。）

Optimal substructure

找出 optimal substructure 的固定套路

  1. 做一個選擇：說明解法的第一步是做某個選擇（第一刀切在哪、最後一次相乘的分割點 k、BST 的 root 是誰……），選完之後剩下一個或多個子問題。
  2. 假設已知最佳選擇：先不管怎麼找到它，假設有人告訴你最佳解做了哪個選擇。
  3. 描述子問題：做了這個選擇之後，剩下哪些子問題？子問題的空間要盡量簡單（例如「長度 \(i\) 的鋼條」、「區間 \([i,j]\)」、「前綴 \(X_i, Y_j\)」）。
  4. Cut-and-paste 證明：如果最佳解裡某個子問題的解不是最佳的，把它「剪掉」換成更好的解，整體就變得更好——矛盾。

不同問題的差異：子問題數 × 選擇數

Optimal substructure 會在兩方面因題而異：(1) 最佳解用到幾個子問題；(2) 決定用哪個子問題時有幾種選擇。大致上 執行時間 ≈ 子問題總數 × 每個子問題的選擇數。

問題子問題子問題數一個解用到選擇數時間
Rod cutting\(r_j\)：長 \(j\) 的鋼條\(\Theta(n)\)1 個（\(r_{j-i}\)）\(j\)\(\Theta(n^2)\)
Matrix-chain\(m[i,j]\)：\(A_i\cdots A_j\)\(\Theta(n^2)\)2 個（左右兩半）\(j-i\)\(\Theta(n^3)\)
LCS\(c[i,j]\)：前綴 \(X_i, Y_j\)\(\Theta(mn)\)1 個≤ 2\(\Theta(mn)\)
Optimal BST\(e[i,j]\)：keys \(k_i..k_j\)\(\Theta(n^2)\)2 個（左右子樹）\(j-i+1\)\(\Theta(n^3)\)

Overlapping subproblems

當遞迴演算法一直重複解同一個子問題，就叫 overlapping subproblems。對照 divide-and-conquer：merge sort 每一層產生的都是全新的子問題，沒有重疊，所以 memoization 幫不上忙（見習題 14.3-2）。

最經典的例子是 Fibonacci：\(F_n=F_{n-1}+F_{n-2}\)。

兩種解決方法：

  1. Bottom-up：決定好順序，從小的子問題開始填表。
  2. Memoization：保留「自然但沒效率」的遞迴寫法，但把每個子問題的答案記下來（memo），再遇到時直接查表。
拼字是 memoization（備忘錄），不是 memorization。投影片寫作 “Memorization”。

重建最佳解

通常把每個子問題做的選擇另外存一張表（rod cutting 的 \(s[j]\)、matrix-chain 的 \(s[i,j]\)、LCS 的 \(b[i,j]\)、OBST 的 \(root[i,j]\)）。重建時每一步 \(O(1)\) 查表，不必重新比較所有選擇。

陷阱：不要誤以為有 optimal substructure

給一個有向圖 \(G=(V,E)\) 和兩點 \(u, v\)：

  • Unweighted shortest path：找 \(u\) 到 \(v\) 邊數最少的路徑 → 有 optimal substructure，適合 DP。
  • Unweighted longest simple path：找 \(u\) 到 \(v\) 邊數最多的 simple path（不重複經過頂點）→ 沒有 optimal substructure，不適合 DP。

最短路徑：有 optimal substructure

設 \(p\) 是 \(u\leadsto v\) 的最短路徑，\(w\) 是 \(p\) 上任一點，把 \(p\) 拆成 \(u\overset{p_1}{\leadsto} w\overset{p_2}{\leadsto} v\)。那麼 \(p_1\) 一定是 \(u\leadsto w\) 的最短路徑。

證明：若有更短的 \(p_1'\)，則 \(u\overset{p_1'}{\leadsto}w\overset{p_2}{\leadsto}v\) 比 \(p\) 短（就算 \(p_1'\) 和 \(p_2\) 共用頂點而形成迴圈，把迴圈拿掉只會更短），與 \(p\) 最短矛盾。∎

最長簡單路徑：沒有 optimal substructure

  • \(q\to r\to t\) 是 \(q\) 到 \(t\) 的一條最長簡單路徑（2 條邊）。
  • 但它的子路徑 \(q\to r\) 不是 \(q\) 到 \(r\) 的最長簡單路徑：\(q\to s\to t\to r\)（3 條邊）更長。
  • \(r\to t\) 也不是 \(r\) 到 \(t\) 的最長：\(r\to q\to s\to t\) 更長。
  • 更糟的是：把兩個子問題的最佳解接起來是 \(q\to s\to t\to r\to q\to s\to t\)，重複經過頂點，連合法解都不是。
為什麼差這麼多關鍵在子問題是否 independent。最短路徑的兩段 \(p_1, p_2\) 不會互相搶頂點（若共用頂點就能抄捷徑，更短）。最長簡單路徑的兩段會搶同一批頂點：前半段用掉的頂點，後半段就不能再用——一個子問題的解會限制另一個子問題能用的「資源」。習題 14.3-5 的「限量鋼條」也是同樣的問題。

事實上，最長簡單路徑是 NP-complete，目前沒有已知的多項式時間演算法。

設計 DP 的四個步驟（CLRS）

  1. Characterize the structure of an optimal solution：找出 optimal substructure。
  2. Recursively define the value of an optimal solution：寫出遞迴式（含 base case）。
  3. Compute the value, typically bottom-up：決定填表順序（或用 memoization）。
  4. Construct an optimal solution from computed information：存下每一步的選擇，回溯出解。
