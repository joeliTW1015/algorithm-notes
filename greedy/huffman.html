Huffman Code 霍夫曼編碼

常出現的字元用短的碼、少出現的用長的碼，可以大幅壓縮檔案。但碼字要怎麼設計才不會解碼出錯、而且總長度最短？Huffman 在 1952 年（還是 MIT 博士生時）給了一個貪婪解。

定長編碼 vs 變長編碼

  • Fixed-length：ASCII 每個字元都用 8 bits。
  • 真實文字中每個字元出現的頻率不同 → variable-length：常見字元用少 bits，少見字元用多 bits。

例子（p.26–27）：100K 個字元的檔案，只有 a–f 六種字元；a 出現 45K 次，其他各 11K 次。

abcdef總 bits
頻率（K）451111111111
定長（3 bits）000001010011100101300K
變長010010111011101111232K

變長：\((45\times1 + 33\times3 + 22\times4)\times 1\text{K}=232\text{K}\) bits，省了約 25%。

「更好」的編碼？Prefix code

再貪心一點：a→0、b→1、c→00、d→01、e→10、f→11，每個碼都更短。問題是收到 0101 時，它可能是 abab、dd、abd、aeb、dab……無法唯一解碼。原因：某個碼字是另一個碼字的前綴（a = 0 是 d = 01 的前綴）。

  • Prefix code（prefix-free code）：沒有任何碼字是另一個碼字的前綴。
  • 解碼很簡單：從頭掃，一湊成某個碼字就輸出那個字元，然後對剩下的部分繼續。不會有歧義。
  • Prefix code tree：每個字元是一個葉子，從根到葉的路徑（左 0、右 1）就是碼字。字元都在葉子上 ⇔ 是 prefix code。

最佳 prefix code 問題

  • Input：字元集合 \(S=\{c_1,\dots,c_n\}\)，\(c_k\) 出現 \(f_{c_k}\) 次。
  • Target：找碼字 \(w_k\) 使 \(\displaystyle B(T)=\sum_k |w_k|\, f_{c_k}\) 最小。\(|w_k|\) 就是 \(c_k\) 在樹 \(T\) 中的深度 \(d_T(c_k)\)。
  • 最佳的樹一定是 full binary tree（每個內部節點都有兩個小孩）：若某節點只有一個小孩，把那個小孩的子樹往上提一層，所有葉子深度減 1，成本變小（15.3-2）。

Greedy-choice property

Lemma 1令 \(c, c'\) 為頻率最小的兩個字元。存在一棵最佳 prefix code tree，其中 \(c\) 和 \(c'\) 是兄弟，而且是最深的兩片葉子。

證明（cut-and-paste）

  1. 令 OPT 為任一最佳樹。若 \(c, c'\) 已經符合要求，得證。
  2. 否則令 \(a, b\) 為 OPT 中最深、而且有同一個 parent 的兩片葉子。為什麼一定存在？最佳樹是 full binary tree，最深的葉子的 parent 有兩個小孩，另一個小孩也在最深那層，不可能是內部節點（否則有更深的葉子），所以也是葉子。
  3. 把 \(a\) 和 \(c\) 交換、\(b\) 和 \(c'\) 交換。為什麼成本不會變大？交換 \(a\) 與 \(c\) 的成本變化是 $$\Delta = (f_c - f_a)\bigl(d(a) - d(c)\bigr)\le 0,$$ 因為 \(f_c\le f_a\)（\(c\) 頻率最小）、\(d(a)\ge d(c)\)（\(a\) 最深）。\(b\) 與 \(c'\) 同理。
  4. 交換後成本 \(\le\) OPT，所以仍是最佳樹，而且 \(c, c'\) 是最深的兄弟。∎

Optimal substructure

令 \(S'\) = 從 \(S\) 拿掉 \(c, c'\)，加入新字元 \(X\)，\(f_X=f_c+f_{c'}\)。

Lemma 2若 \(T'\) 是 \(S'\) 的最佳 prefix code tree，則把 \(T'\) 中的葉子 \(X\) 換成「有兩個小孩 \(c, c'\) 的內部節點」得到的樹 \(T\)，是 \(S\) 的最佳 prefix code tree。

關鍵等式：\(c, c'\) 的深度是 \(d_{T'}(X)+1\)，其餘字元深度不變，所以

$$B(T) = B(T') - f_X\,d_{T'}(X) + (f_c+f_{c'})\bigl(d_{T'}(X)+1\bigr) = B(T') + f_c + f_{c'}.$$

證明（反證）

  1. 假設 \(T\) 不是 \(S\) 的最佳樹，則存在最佳樹 \(T''\) 使 \(B(T'')<B(T)\)。由 Lemma 1，可以假設 \(T''\) 中 \(c, c'\) 是兄弟。
  2. 把 \(T''\) 中 \(c, c'\) 的 parent 換成葉子 \(X\)，得到 \(S'\) 的樹 \(T'''\)。由同一個等式： $$B(T''') = B(T'') - f_c - f_{c'} < B(T) - f_c - f_{c'} = B(T').$$
  3. 這和 \(T'\) 是 \(S'\) 的最佳樹矛盾。∎

Huffman 演算法

兩個 lemma 合起來：合併頻率最小的兩個字元 → 對縮小一個字元的 \(S'\) 遞迴 → 把 \(X\) 展開成 \(c, c'\)。

找出頻率最小的 c 和 c'
S' = S - {c, c'} + {X}, fX = fc + fc'
T' = Huffman(S')
把 T' 的葉子 X 接上 c 和 c' 兩個小孩
return 這棵樹

n = |C|
Q = C              // min-priority queue
for i = 1 to n - 1
    allocate a new node z
    z.left = x = EXTRACT-MIN(Q)
    z.right = y = EXTRACT-MIN(Q)
    z.freq = x.freq + y.freq
    INSERT(Q, z)
return EXTRACT-MIN(Q)  // 樹根

下面預設是投影片 p.42（CLRS 圖 15.5）的例子 f:5 e:9 c:12 b:13 d:16 a:45，合併順序 14 → 25 → 30 → 55 → 100。也可以換成 p.26 的頻率，會發現 Huffman 得到的成本正好是 232K——投影片 p.27 的編碼已經是最佳的。

執行時間：\(O(n\log n)\)

  • 用 binary min-heap 當 \(Q\)：BUILD-MIN-HEAP \(O(n)\)。
  • 迴圈跑 \(n-1\) 次，每次 2 次 EXTRACT-MIN + 1 次 INSERT，各 \(O(\lg n)\)。
  • 總共 \(O(n\log n)\)。（若用 van Emde Boas tree 可降到 \(O(n\lg\lg n)\)。）
