Chapter 15 · Greedy Algorithms

每一步都選現在看起來最好的

貪婪法不回頭、不比較所有子問題：做一個局部最佳的選擇，剩下一個子問題，再重複。難的不是寫程式，而是證明這樣做是對的——或者舉出反例說明它不對。右邊是活動選擇：依結束時間掃一遍就得到最佳解。

每一頁都有可以一步一步執行的互動元件（鍵盤 ← → 也能操作），以及投影片所有例題、反例和指定習題的詳解。

設計並證明一個貪婪演算法

  1. 定一個貪婪選擇：例如「最早結束的活動」、「密度最大的物品」、「頻率最小的兩個字元」。做了這個選擇後，只剩一個子問題。
  2. 證明 greedy-choice property：存在某個最佳解包含這個貪婪選擇。標準手法是 exchange / cut-and-paste：拿任一最佳解 OPT，把它的某個元素換成貪婪選擇，證明仍然合法、而且不會變差。
  3. 證明 optimal substructure：貪婪選擇 + 子問題的最佳解 = 原問題的最佳解。通常用反證：如果子問題的部分不是最佳，換成更好的就會讓整體比 OPT 更好，矛盾。
  4. 寫成迴圈並分析時間：通常先排序（\(O(n\log n)\)）或用 priority queue，然後線性掃描。

考前檢查清單

  • 能說出 greedy-choice property 和 optimal substructure 的定義，以及兩者各自讓我們得到什麼（「第一步選對」、「之後遞迴下去也對」）。
  • 能對活動選擇、fractional knapsack、Huffman 寫出 cut-and-paste 交換論證。
  • 能舉出反例：找零錢 {1, 4, 5, 10}、活動選擇的最短時間 / 最早開始 / 最少衝突、0-1 knapsack 的密度優先。
  • 能手動跑 GREEDY-ACTIVITY-SELECTOR 和 HUFFMAN（畫出每一輪的森林、寫出碼字、算 \(\sum f\cdot|w|\)）。
  • 能分析時間：活動選擇 \(O(n)\)（已排序）、Huffman \(O(n\log n)\)（為什麼用 heap）、fractional knapsack \(O(n\log n)\) / \(O(n)\)。
  • 能分辨 prefix code 與非 prefix code，說明為什麼 prefix code 能唯一解碼。

投影片補充說明

  • p.27 的編碼（a→0、b→100、…，232K bits）其實就是這組頻率的最佳 prefix code：用 Huffman 算也是 232K。→
  • p.17「If finish times are sorted, running time = \(O(n)\)」：沒有排序時要先排序，總時間 \(O(n\log n)\)。
  • p.18 的最佳解不唯一：\(\{a_1,a_3,a_6,a_8\}\) 和 \(\{a_2,a_5,a_7,a_9\}\) 都是 4 個。後者正好是「最晚開始」貪婪（15.1-2）的結果。→
  • p.21 說 0-1 knapsack 是 NP-complete，但 15.2-2 的 DP 是 \(O(nW)\)——不矛盾：\(W\) 的輸入長度只有 \(\lg W\) 位元，\(O(nW)\) 是 pseudo-polynomial。
  • p.42–43 同頻率時誰先取出會影響樹的形狀和碼字，但不影響總成本。本站的 tie-break（先放進 Q 的先取出）會畫出和投影片一模一樣的圖。
