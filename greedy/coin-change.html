Coin Changing 找零錢

最直覺的貪婪法：每次都拿最大的硬幣。它在台灣、美國的硬幣上都對，但換一組面額就可能錯。從這個例子看出設計貪婪演算法要證明的兩件事。

問題

某個國家的硬幣面額是 $1, $2, $5, $10。設計一個演算法，對任意金額 \(x\)，用最少枚數的硬幣湊出 \(x\)。

貪婪找零

bag = ∅                     // 1. 空袋子
while x > 0                 // 2.
    c = 不超過 x 的最大硬幣
    把 c 放進 bag
    x = x - c
return bag                  // 3.
  • 每一輪都拿 \(c\le x\)，最後總和一定剛好是 \(x\)（演算法正確地「湊出」\(x\)）。
  • 每一步都做一個 greedy choice：拿最大的硬幣，因為它「看起來」最能減少枚數。這就是貪婪演算法。

貪婪不一定對

換成面額 $1, $4, $5, $10，要找 $8：

找法枚數
貪婪5 + 1 + 1 + 14
最佳4 + 42

怎麼判斷如果一組面額有反例，最小的反例一定小於「最大兩個面額的和」（Kozen & Zaks, 1994）。所以只要檢查有限多個 \(x\) 就能判斷這組面額適不適合貪婪——上面的元件就是這樣判斷的。一般面額請用 DP（Problem 15-1(d)），\(O(nk)\)。

為什麼 $1, $2, $5, $10 時貪婪是對的

看任何一個最佳找法，它不可能包含以下組合（否則可以換成更少枚）：

  • 兩個 $1 → 換成一個 $2；三個 $2 → 換成 $5 + $1；$2 + $2 + $1 → 換成 $5；兩個 $5 → 換成 $10。

剩下能出現的組合中，$1、$2、$5 合計最多 $5 + $2 + $2 = 9 元，所以最佳解的 $10 個數一定是 \(\lfloor x/10\rfloor\)，跟貪婪一樣。同理 $1、$2 合計最多 $2 + $2 = 4 元，所以 $5 的個數也和貪婪一樣；最後 $1 最多一個，$2 的個數也一樣。也就是說，最佳解就是貪婪的找法。

設計貪婪演算法：兩大性質

重點
  1. Greedy-choice property：做局部最佳（貪婪）的選擇，能得到全域最佳解。
  2. Optimal substructure：問題的最佳解包含子問題的最佳解。

要證明一個貪婪演算法是對的，通常分兩步：

  1. 某個最佳解包含貪婪選擇 ⇒ 第一步選貪婪選擇不會錯。（通常用 cut-and-paste / exchange：把最佳解中的某個元素換成貪婪選擇，仍是最佳解。）
  2. Optimal substructure ⇒ 做完選擇後，剩下的子問題用同樣方法遞迴解就好，合起來仍然最佳。

找零錢在 {1, 4, 5, 10} 時第 1 步就不成立：找 8 元的所有最佳解（只有 4+4）都不含 $5。
